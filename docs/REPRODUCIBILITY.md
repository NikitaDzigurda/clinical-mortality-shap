# Воспроизведение и происхождение результатов

## Три разных уровня воспроизведения

1. **Проверка сохранённых результатов:** пересчитать метрики из OOF, проверить разбиения и исходы, загрузить модели, сопоставить их прогнозы с сохранённым SHAP. Это выполняет `python scripts/verify_repository.py`. Нового подбора гиперпараметров здесь нет.
2. **Повторное объяснение сохранённых моделей:** выполнить ноутбук 03 через `run_notebooks.py --stage shap`. Он использует копию сохранённой модели и публичную матрицу, затем пересчитывает SHAP. Новые объяснения записываются в `runs/`.
3. **Полный повтор исследования:** последовательно выполнить 01 → 02 → 03. Код вновь проводит весь подбор и обучение. Эта процедура затратна; таблицы испытаний и исходные результаты сохраняются отдельно от новых.

## Окружение

Исходные основные расчёты выполнены в Python 3.11.15. Версии NumPy 2.4.6, pandas 3.0.3, scikit-learn 1.9.0, Optuna 5.0.0, SHAP 0.51.0, CatBoost 1.2.10, XGBoost 3.2.0. Остальные зависимости указаны в requirements.txt. Для старых поисковых ноутбуков дополнительно могут требоваться statsmodels, seaborn, imbalanced-learn, openpyxl и xlrd; их наличие не делает исходные приватные таблицы публично доступными.

Ноутбуки больше не требуют конкретного локального имени пользователя или абсолютного пути к Conda. Корень определяется по файлу `scripts/repository_support.py`. Все модели обучаются с ограничением числа вычислительных потоков, заданным в исходном коде. Основной seed — 2026; конкретные повторения, блоки и этапы имеют производные seeds, описанные в коде и протоколах.

## Запуск

Из корня репозитория создайте среду и установите requirements.txt, затем зарегистрируйте её ядро, как указано в README. Для просмотра подходит Jupyter; для воспроизведения с чистыми ядрами — CLI:

```bash
python scripts/run_notebooks.py --cohort acs --stage data --kernel clinical-mortality-shap
python scripts/run_notebooks.py --cohort vascular --stage data --kernel clinical-mortality-shap
python scripts/run_notebooks.py --cohort acs --stage shap --kernel clinical-mortality-shap
python scripts/run_notebooks.py --cohort vascular --stage shap --kernel clinical-mortality-shap
```

`--stage all` включает повторную оптимизацию. `--stage models` повторяет только обучение и формирование новых OOF; после него необходимо вновь выполнить `--stage shap`. Отдельный новый baseline ОКС: `python scripts/run_default_baseline.py`; он читает рабочие разбиения и не меняет снимок в results/.

Скрипт запуска не устанавливает зависимости сам и не меняет глобальное окружение. В случае ошибки выполненный до неё ноутбук сохраняется в runs/ для диагностики. Директория runs/ исключена из Git. Для полностью нового повторения можно переименовать уже созданную рабочую папку `runs/acs` или `runs/vascular` и запустить заново; исходные результаты останутся в results/.

## Что хранится в results/

Снимки включают OOF-прогнозы, метрики блоков и повторений, trials Optuna, выбранные конфигурации, разбиения, условные сравнения, данные калибровки, две окончательные модели joblib, массивы SHAP и исследовательские графики. JSON-протоколы сохраняют RUN_ID исходного расчёта. Их оригинальные data/code hashes относятся к локальному снимку до экспорта; это не hashes очищенных ноутбуков. Для проверки опубликованных файлов используется отдельный экспортный манифест.

При создании рабочей копии `repository_support.initialize()` заменяет hash исходной матрицы в рабочих JSON на hash публичного CSV и записывает `PUBLIC_EXPORT.json`. Изменились технические групповые коды и удалён source_row; признаки и исходы не изменились. Такая операция не объявляется новым обучением. Файлы моделей не переписываются. NPZ с групповыми кодами изменены только в этих кодах; исходные и экспортные hashes приведены отдельно.

Кеши SQLite исходных Optuna studies не включены. Таблицы trials.csv сохраняют параметры, значения целевой функции, состояния и сведения об испытаниях. При полном запуске создаются новые SQLite. Нельзя ожидать восстановления старого состояния sampler только из CSV; путь воспроизведения здесь — новый запуск из исходного seed и проверка сохранённого результата отдельно.

## Изменения кода при подготовке репозитория

- Заменён локальный bootstrap, удалено требование конкретного интерпретатора.
- Ноутбук 01 проверяет готовую обезличенную матрицу; первичный разбор медицинских файлов не исполняется на открытом наборе.
- Структура и индексы обучающих ячеек 02 сохранены; функции подготовки, отбора, подбора, обучения и оценки перенесены из фактического исследования.
- В 03 сохранены ядро SHAP, построение графиков и индивидуальных примеров; в сосудистой задаче сохранён анализ ошибок.
- Постобработка, ожидавшая приватные архивы и старые локальные журналы, заменена независимым скриптом проверки снимков.
- Выводы, временные метки исполнения и лишние метаданные ноутбуков очищены.

В конце публичного 03 проверяется сохранённый снимок results/, а не качество заново настроенной модели из runs/. Это различие нужно учитывать при интерпретации отчёта.

## Выполненная проверка при сборке

Численные результаты проверки зафиксированы в `verification/recorded_results_check.json`: заново вычислены 198 блоковых записей для ОКС и 216 для сосудистой задачи, включая основные и контрольные варианты. Проверены соответствие y, уникальность и покрытие OOF, групповое разделение, численные прогнозы повторно загруженных окончательных моделей и аддитивность сохранённых SHAP.

Дополнительный отчёт `verification/portable_execution_check.json` фиксирует именно реально выполненные этапы подготовки репозитория. Полный поиск Optuna при упаковке не повторяется; это ограничение отделено от успешной проверки сохранённых расчётов.

В чистых ядрах выполнены ноутбуки 01 и 03 для обеих когорт без ошибок ячеек. Пройдены также 16 пробных обучений фактическими функциями ноутбуков 02: четыре семейства на полном и сокращённом обучающем наборе каждой задачи. Сценарий — `python scripts/smoke_training.py`, отчёт — `verification/training_smoke_check.json`. Это проверка переносимости обучающих функций, а не повтор всего поиска Optuna. При завершении ядер ограниченная локальная среда выдала предупреждение ipykernel о запрете перечисления процессов; выполнение ячеек завершилось успешно.
